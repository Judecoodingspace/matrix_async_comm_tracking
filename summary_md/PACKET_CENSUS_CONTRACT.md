# Passive Packet Census Contract

## 1. Purpose

This contract defines a future **passive descriptive census** of the four
logical packet channels in the frozen MDMT/MIA asynchronous runtime at commit
`c3332d2d33d054a135480c4c05ca9adba3fc2b7c`.

The census is limited to four questions:

1. How many current logical packets are emitted by each channel and stage?
2. How large is each packet under two explicitly named software-level size
   definitions?
3. Can every emission be linked to exactly one auditable terminal fate?
4. What are the channel/stage distributions of frequency, size, and raw
   content counts?

The unit of observation is one call to the current asynchronous runtime's
`_wire()` emission path. The census does not redefine that unit as a physical
network packet.

### Research question and evidence classification

- **FACT:** `_wire()` creates one canonical JSON representation for each
  current logical packet, and `_send()` either consumes it immediately or
  places it in a channel queue.
- **FACT:** current terminal paths do not consistently retain a stable packet
  key or the emission `wire_digest`.
- **FACT:** Homography installation and later held-state use are different
  events.
- **INFERENCE:** a ledger-only lineage key plus passive byte/count bookkeeping
  is sufficient to close a one-emission/one-fate census without changing MIA
  semantics.
- **ASSUMPTION TO TEST:** adding the census sidecar does not change execution
  order, random state, payload bytes, tracker feedback, or predictions.
- **UNKNOWN:** physical packetization, link framing, endpoint overhead,
  compression, retransmission, and capacity.

Primary hypothesis:

> The current logical emissions can be measured and conserved with passive
> instrumentation only.

Alternative hypothesis:

> At least one current terminal path cannot be linked or counted without
> changing a semantic runtime path, so the census is not scientifically
> closed.

## 2. Non-goals

This contract does not authorize or define:

- dataset, detector, tracker, MIA, evaluation, or GT execution;
- a packet census run;
- physical wireless traffic or PHY/MAC payload;
- bandwidth, Mbps, KB/frame bandwidth, service time, queue capacity, loss,
  retransmission, or transport framing;
- FIFO, Round Robin, EDF, STS, priority, channel weights, or any scheduler;
- new packet atomicity or endpoint semantics;
- changes to Local readiness, Homography hold, ID version handling,
  Supplement expiry, tracker feedback, or author outputs;
- Work 1, `S_cf`, `Yec`, Route A, or any correctness oracle.

No result from a future census may be interpreted as communication-system
performance without a separate research decision.

## 3. Packet identity

### 3.1 Audit of `source_state_version`

`source_state_version` is generated by the process-global monotonic
`_packet_version` counter in `_wire()`. Within one normally initialized
`PacketRuntime` instance it is an auditable emission order and is expected to
be unique. It is not sufficient as the sole durable packet lineage key because:

- it has no run or sequence namespace;
- it is semantically an existing source-state/order version;
- current terminal records do not consistently carry it;
- merging ledgers from multiple runtime instances could create equal values.

It remains required metadata and must not be redefined.

### 3.2 Runtime-instance audit

The generated author entry contains one textual `PacketRuntime(...)`
construction inside its sequence-processing invocation, but neither
`PacketRuntime.__init__` nor the launcher establishes a process-wide or
launch-wide invariant that a given `(census_run_id, sequence_name)` can have
only one instance. A future launcher could invoke the same sequence twice,
instantiate a second runtime for retry/inspection, or merge artifacts from
separate processes. Therefore the two-part namespace cannot be treated as a
strict uniqueness proof.

### 3.3 Frozen independent lineage key

Every emission receives a census-side `packet_id` whose logical value is the
immutable tuple:

```text
(census_run_id, sequence_name, runtime_instance_id, emission_ordinal)
```

The JSON representation is:

```json
{
  "census_run_id": "<launch-frozen non-semantic run identifier>",
  "sequence_name": "<current PacketRuntime sequence_name>",
  "runtime_instance_id": "<initialization-time non-semantic audit identifier>",
  "emission_ordinal": 1
}
```

Rules:

- `census_run_id` is fixed before launch and cannot depend on GT, candidates,
  tracking output, payload content, or future outcome.
- `runtime_instance_id` is created once at `PacketRuntime` initialization and
  is non-semantic audit metadata. It cannot depend on GT, payload, candidates,
  tracking output, or future state.
- `emission_ordinal` is a new one-based, monotonically increasing
  instrumentation counter assigned exactly once when `_wire()` successfully
  creates an emission.
- The ordinal may numerically equal `source_state_version` in the frozen
  runtime, but it is a different field with a different semantic role.
- The complete four-field object is the identity; validators compare its
  canonical JSON value, not Python object identity.
- `packet_id` is census sidecar metadata. It must not be inserted into or
  hashed as part of the existing logical wire packet.
- The same `packet_id` and emission `wire_digest` must travel together in an
  out-of-band census sidecar through immediate and queued paths.

This freezes packet lineage without merging it with runtime state versioning.

## 4. Emission schema

The emission ledger is append-only JSONL. Exactly one record is appended after
the existing canonical `encoded` string has been created and before the packet
is returned or queued. No future outcome is written into this record.

Required common fields:

| Field | Frozen meaning |
| --- | --- |
| `record_type` | Constant `PACKET_EMISSION`. |
| `packet_id` | Immutable object defined in Section 3. |
| `channel` | Exact runtime channel: `local`, `homography`, `id_state`, or `supplement`. |
| `stage` | Exact payload stage when present; otherwise `NOT_EXPLICIT`. |
| `runtime_instance_id` | Copy of the non-semantic initialization-time identifier contained in `packet_id`. |
| `source_state_version` | Existing wire value, unchanged. |
| `capture_frame` | Existing wire value. |
| `emitted_frame` | Existing wire value. |
| `arrival_frame` | Existing planned/current arrival frame in the wire. |
| `valid_until_frame` | Existing wire value; not interpreted as a universal deadline. |
| `wire_digest` | Existing canonical-wire SHA-256 defined below. |
| `JSON_WIRE_BYTES` | Exact primary size quantity defined in Section 7. No lowercase or physical-byte alias is permitted. |
| `SEMANTIC_ARRAY_RAW_BYTES` | Exact primary size quantity defined in Section 8. No scalar/list accounting is included. |
| `routing_attribution` | Source-native routing object defined below. |
| `content_counts` | Channel-specific raw counts from Section 6. |

`wire_digest` is fixed to the current runtime's `wire_digest` calculation:

```text
sha256(encoded.encode("utf-8")).hexdigest()
```

It covers the complete current canonical logical wire object, not only
`wire["payload"]`. The exact emission string is hashed once; terminal records
propagate that stored digest and do not reserialize the packet.

### Routing attribution

Routing must preserve native evidence and must not infer missing endpoints:

| Channel | `routing_attribution` |
| --- | --- |
| Local | `{"type":"VIEW_NATIVE","view_id":<payload view_id>,"source":"NOT_EXPLICIT","target":"NOT_EXPLICIT","direction":"NOT_EXPLICIT"}` |
| Homography | `{"type":"DIRECTION_NATIVE","direction":<payload direction>,"source":"NOT_EXPLICIT","target":"NOT_EXPLICIT"}` |
| ID state | `{"type":"PARTIAL_NATIVE","stage":<payload stage>,"remap_event_view_ids":[<sorted unique native view_id values>],"source":"NOT_EXPLICIT","target":"NOT_EXPLICIT","direction":"NOT_EXPLICIT"}` |
| Supplement | `{"type":"BUNDLED","stage":<payload stage>,"source":"NOT_EXPLICIT","target":"NOT_EXPLICIT","direction":"NOT_EXPLICIT"}` |

An empty ID remap list produces an empty `remap_event_view_ids` list. Stage
names are retained as strings but are not parsed to manufacture endpoints.

## 5. Terminal schema

The terminal ledger is a separate append-only JSONL. Each emitted `packet_id`
must have exactly one terminal record after sequence finalization.

Required fields:

| Field | Frozen meaning |
| --- | --- |
| `record_type` | Constant `PACKET_TERMINAL`. |
| `packet_id` | Exact emission-side lineage key. |
| `channel` | Copied emission channel for partitioned validation. |
| `stage` | Copied emission stage for partitioned validation. |
| `routing_attribution` | Copied emission attribution; no new inference at arrival. |
| `terminal_class` | One of the five classes below. |
| `terminal_reason` | Existing native action where one exists, or the explicitly marked source-branch observation listed in Section 10. |
| `terminal_frame` | Frame in which the terminal branch is processed; for finalization, the final processed frame. |
| `wire_digest` | The stored emission `wire_digest`, propagated without reserialization. |

Allowed terminal classes are exactly:

```text
TIMELY_DELIVERED
ARRIVED_ACCEPTED
ARRIVED_REJECTED
EXPIRED
PENDING_AT_END
```

`queued`, `_drain()` availability, and Homography `held` use are not terminal
classes. A terminal record describes packet lifecycle, not every semantic
effect caused by its payload.

If execution aborts before the sequence finalizer runs, the census is
`CENSUS_INCOMPLETE`; a validator must not synthesize successful conservation
from a partially written ledger.

## 6. Channel-specific content counts

These fields are descriptive raw counts only. They are not scheduler features,
quality estimates, utility estimates, or correctness labels.

### Local

Directly available:

```text
tracker_row_count
detector_candidate_count
```

They are the leading-dimension lengths of `tracker_rows` and
`detector_candidates`, including zero.

### Homography

Directly available:

```text
matrix_present
previous_matrix_present
matching_point_count
matrix_element_count
previous_matrix_element_count
estimation_mode
```

`matrix_present` and `previous_matrix_present` are boolean indicators of a
nonzero element count. `estimation_mode` is copied exactly from the current
payload (`estimated` or `fallback`); it is not a new quality judgment.

### ID state

Directly available:

```text
track_rows_view1_count
track_rows_view2_count
remap_event_count
```

The current payload has only one untagged `matched_ids` list and one untagged
`confirmed_ids` list. It does not carry per-view lists or per-item view tags.
Under frozen `R-CENSUS-COUNT-01`, the permitted source-native descriptive
fields are:

```text
shared_matched_id_count = len(current payload matched_ids)
shared_confirmed_id_count = len(current payload confirmed_ids)
```

`shared` means only that the current runtime carries a shared list. It does
not express source, target, view1, or view2 ownership. The census must not
deduplicate, remap, infer ownership from rows/stage/ID values, check
correctness, or read GT. The raw track-row counts are included because the
current logical payload serializes both two-view state arrays.

### Supplement

Directly available:

```text
track_rows_view1_count
track_rows_view2_count
supplement_view1_row_count
supplement_view2_row_count
score_stage
low_score_flag
```

`score_stage` is the exact payload `stage`; `low_score_flag` is the exact
existing `low_score` value. No high/low stage is inferred from result content.

As with ID state, the current Supplement payload supplies only untagged shared
`matched_ids` and `confirmed_ids` lists. Under frozen
`R-CENSUS-COUNT-01`, the permitted source-native descriptive fields are:

```text
shared_matched_id_count = len(current payload matched_ids)
shared_confirmed_id_count = len(current payload confirmed_ids)
```

`shared` has no source/target/view ownership semantics. No total
reinterpretation, deduplication, remapping, correctness check, or GT read is
permitted.

No count that requires GT, candidate identity, correctness, future state, or
an inferred endpoint is allowed. A requested field absent from these payloads
must be recorded as `NOT_DIRECTLY_AVAILABLE`, not reconstructed from outputs.

## 7. `JSON_WIRE_BYTES` definition

The primary field name is fixed as:

```text
JSON_WIRE_BYTES
```

For each emission:

```text
JSON_WIRE_BYTES = len(encoded.encode("utf-8"))
```

where `encoded` is the exact string already produced by current `_wire()`:

```python
json.dumps(_json_safe(wire), sort_keys=True, separators=(",", ":"))
```

The census must count that existing string directly. It must not reserialize a
decoded packet and assume byte equality. Census-only `packet_id`, ledgers, and
terminal metadata are excluded because they are not part of the frozen
logical wire.

`JSON_WIRE_BYTES` means the size of the current software logical packet's
canonical serialized representation. It is valid for descriptive census only.

## 8. `SEMANTIC_ARRAY_RAW_BYTES` definition

The second and only other primary size field is fixed as:

```text
SEMANTIC_ARRAY_RAW_BYTES
```

For each semantic NumPy array passed to the channel's current `_encode_array`
path:

```text
array_raw_bytes = np.ascontiguousarray(original_array).nbytes
SEMANTIC_ARRAY_RAW_BYTES = sum(array_raw_bytes for all such payload arrays)
```

The arrays included exactly once are:

| Channel | Included arrays |
| --- | --- |
| Local | `tracker_rows`, `detector_candidates` |
| Homography | `matrix`, `previous_matrix` |
| ID state | `track_rows_view1`, `track_rows_view2` |
| Supplement | `track_rows_view1`, `track_rows_view2`, `supplement_view1`, `supplement_view2` |

The computation occurs as passive sidecar bookkeeping at the existing array
encoding boundary. It must not cast, reshape, mutate, or copy a value back into
the runtime payload.

This quantity excludes:

- JSON syntax and dictionary keys;
- base64 expansion;
- scalar and list storage;
- dtype/shape metadata text;
- packet envelope/header bytes;
- transport framing or link overhead.

## 9. Explicitly forbidden byte interpretations

The following quantities remain undefined and are not aliases for either
primary size field:

```text
PHYSICAL_COMMUNICATION_BYTES
METADATA_OVERHEAD_BYTES
TOTAL_NETWORK_BYTES
PHYSICAL_NETWORK_PAYLOAD
PHY_OR_MAC_PAYLOAD
Mbps
KB_PER_FRAME_BANDWIDTH
```

No custom scalar/list accounting rule may be introduced in this census.

JSON/base64 reflects the current in-process software representation. It cannot
support a physical capacity claim until packet atomicity, endpoints, framing,
transport, compression, and retransmission receive separate frozen decisions.

## 10. Runtime-event to terminal-class mapping

The table distinguishes current native actions from contract-level terminal
classification. `REQUIRES_PASSIVE_INSTRUMENTATION` means the current event
lacks packet ID/`wire_digest` propagation or lacks a packet-level completion record;
it does not authorize a semantic branch change.

| Runtime path / native action | Terminal class | `terminal_reason` | Instrumentation status |
| --- | --- | --- | --- |
| `_send()`: `packet_action="timely"` | `TIMELY_DELIVERED` | exact native value `timely` | Requires packet ID and stored `wire_digest` sidecar only. |
| `_send()`: `packet_action="queued"` | none | none | Nonterminal emission/queue event. |
| `_drain()`: packet becomes available | none | none | Nonterminal availability event. |
| `_drain()`: `capture_frame > frame_id`, current future-read violation/drop branch | `ARRIVED_REJECTED` | source-branch label `future_read_violation` | `REQUIRES_PASSIVE_INSTRUMENTATION`; current code increments a counter but emits no packet terminal. |
| `begin_frame()`, Local: `packet_action="expired"` | `EXPIRED` | exact native value `expired` | `REQUIRES_PASSIVE_INSTRUMENTATION` for packet ID/`wire_digest`. |
| `begin_frame()`, Homography arrival: `packet_action="applied"` after installing `_latest_h` | `ARRIVED_ACCEPTED` | exact native value `applied` | `REQUIRES_PASSIVE_INSTRUMENTATION` for packet ID/`wire_digest`. |
| `deliver_homography()`: `packet_action="held"` | none | none | Semantic-usage event, not a packet terminal. |
| `_apply_pending_id()`: packet version `<= _last_id_packet_version`, native `packet_action="obsolete"` | `ARRIVED_REJECTED` | exact native value `obsolete` | `REQUIRES_PASSIVE_INSTRUMENTATION` for packet ID/`wire_digest`. |
| `_apply_pending_id()`: packet version accepted and whole payload processing completes | `ARRIVED_ACCEPTED` | source-branch label `id_version_accepted` | `REQUIRES_PASSIVE_INSTRUMENTATION`; current code has no single packet-level completion event. |
| ID remap subevent: native `applied`, `conflict`, or row-missing `obsolete` | none by itself | retain only in an optional subevent audit | Multiple remap subevents must not create multiple packet terminals. |
| `begin_frame()`, Supplement: `packet_action="expired"` | `EXPIRED` | exact native value `expired` | `REQUIRES_PASSIVE_INSTRUMENTATION` for packet ID/`wire_digest`. |
| `finalize()`: `packet_action="pending_at_end"` | `PENDING_AT_END` | exact native value `pending_at_end` | `REQUIRES_PASSIVE_INSTRUMENTATION` for packet ID/`wire_digest`. |

`future_read_violation` and `id_version_accepted` are explicitly marked
source-branch labels added by the census contract because no packet-level
native `packet_action` exists at those points. They must not be represented as
pre-existing runtime reason strings.

For an accepted ID packet, remap-level conflict/obsolete/applied counts may be
reported as passive subevent counts. The packet still reaches
`ARRIVED_ACCEPTED` after the source accepts its version and finishes processing
the payload, because matched/confirmed lists are also consumed. A remap
subevent is not an independent packet.

## 11. Homography packet lifecycle versus held-state usage

The following events are distinct:

```text
H packet emitted
  -> timely delivered OR queue
  -> delayed arrival installs matrix as latest H
  -> exactly one packet terminal

installed latest H
  -> may be used as held state on zero or more later frames
  -> semantic usage only
```

Installing a delayed H packet in `_latest_h` is the packet's
`ARRIVED_ACCEPTED` terminal. Every later `held` use refers to stored semantic
state and must not produce another packet terminal.

If a future H usage ledger is desired, it must be a separate append-only
semantic-usage artifact keyed to the installed H packet where source evidence
permits. It is excluded from all packet conservation equations and is not part
of this census contract.

## 12. Conservation equations

Let `E` be the multiset of emission records and `T` the multiset of terminal
records after a successful sequence finalization.

Global conservation:

```text
|E| = |T|

|T| =
  N_TIMELY_DELIVERED
  + N_ARRIVED_ACCEPTED
  + N_ARRIVED_REJECTED
  + N_EXPIRED
  + N_PENDING_AT_END
```

Lineage conservation for every `packet_id = p`:

```text
count(E where packet_id = p) = 1
count(T where packet_id = p) = 1
wire_digest(E[p]) = wire_digest(T[p])
```

The same equations must hold independently for every observed:

```text
channel
(channel, stage)
(channel, stage, routing_attribution)  # only source-native attribution
```

The routing object is compared in canonical JSON form. `NOT_EXPLICIT` and
`BUNDLED` are valid explicit categories; they must not be dropped from grouped
counts. Cross-channel or cross-stage cancellation is forbidden.

## 13. Conservation gates

All gates are mandatory. No census result may be interpreted if any gate
fails.

| Gate | Requirement | Exact pass condition |
| --- | --- | --- |
| C1 Packet ID uniqueness | No two logical emissions share a lineage key. | `duplicate_packet_id = 0` |
| C2 Exactly one emission | Each emitted ID has one emission record. | `emission_count_per_packet_id = 1` |
| C3 Exactly one terminal fate | Each emitted ID has one terminal after finalize, including pending packets. | `terminal_count_per_emitted_packet_id = 1` |
| C4 No phantom terminal | Every terminal has an emission. | `terminal_without_emission = 0` |
| C5 No orphan emission | Every emission has a terminal after finalize. | `emission_without_terminal = 0` |
| C6 No duplicate terminal | No packet has two terminal records. | `duplicate_terminal = 0` |
| C7 Wire digest conservation | Emission and terminal retain the same exact canonical-wire digest. | `wire_digest_mismatch = 0` |
| C8 Count conservation | Total and partitioned emission counts equal terminal counts. | all global/channel/stage/source-native-routing differences equal `0` |

Additional measurement gates:

- ledger JSON schema validation passes;
- every terminal class is in the frozen five-value set;
- every directly available size/count field is present and nonnegative;
- `shared_matched_id_count` and `shared_confirmed_id_count`, where emitted,
  equal the direct length of the current payload lists without deduplication or
  ownership inference;
- `JSON_WIRE_BYTES` equals a direct count of the emission's existing encoded
  string;
- `SEMANTIC_ARRAY_RAW_BYTES` equals the sum over the frozen channel array set;
- `packet_id` and all census fields are absent from the existing logical wire;
- abnormal termination cannot be reported as a conserved census.

`PENDING_AT_END` is a real auditable fate, not deletion or implicit expiry.
Remaining queued packets are recorded exactly once during successful finalize.

## 14. Passive instrumentation boundary

Future implementation is authorized only to:

- allocate the independent ledger-only `packet_id`;
- count bytes on the existing canonical `encoded` string;
- sum raw bytes at current array-encoding boundaries;
- record the frozen content counts and native routing evidence;
- carry `packet_id` and the stored `wire_digest` in an out-of-band sidecar;
- append one emission and one terminal record;
- record `PENDING_AT_END` during finalization;
- run schema, uniqueness, `wire_digest`, and conservation validators.

It must not:

- alter `wire`, `wire["payload"]`, the canonical JSON string, or its `wire_digest`;
- alter queue keys, service order, delays, arrival frames, or readiness;
- read or change detector, tracker, Kalman, identity, H estimation, Supplement,
  NMS, feedback, or publication state;
- modify Homography hold, ID version/remap logic, Local deadline behavior, or
  Supplement expiry;
- read GT, XML correctness identity, future state, evaluation output, Work 1,
  `S_cf`, or `Yec`;
- influence any runtime branch from a census count, size, or ledger value.

All ledger paths must be isolated from author result paths. I/O failure must
fail the census claim closed; it must not change or retry author semantic work.

## 15. Non-interference gate

A future instrumentation implementation must be tested under identical frozen
runtime conditions with:

```text
census OFF
vs
census ON
```

The only authorized treatment difference is passive census artifact creation.
Required exact equalities:

```text
prediction JSON bytes                      equal
existing logical packet wire-digest order equal
existing manifest semantic counts            equal
tracker feedback digest sequence              equal
```

Additional requirements:

- random-state snapshots before/after instrumentation calls are unchanged;
- packet emission and consumer call order are unchanged;
- no census field appears in the logical packet payload;
- no unmatched or duplicate logical packet appears between OFF and ON;
- the ON run alone passes C1-C8.

Any difference is `CENSUS_INSTRUMENTATION_INTERFERENCE` and blocks a census
run. No tolerance, reordered multiset comparison, or metric-only equivalence
may rescue an exact mismatch.

## 16. Remaining unresolved decisions

The following remain `NEEDS_RESEARCH_DECISION` before any physical network or
scheduler study, but do **not** block the passive descriptive census:

1. whether canonical JSON/base64 is only an audit representation or a future
   communication payload format;
2. physical packet atomicity, especially bundled ID and Supplement state;
3. explicit source, destination, direction, and link semantics where the
   current payload does not provide them, including per-view ownership of the
   shared matched/confirmed ID lists;
4. metadata/header/framing/compression/retransmission accounting;
5. physical capacity, bandwidth, service time, queue policy, loss, deadline,
   priority, and channel weights;
6. whether channel-specific validity semantics should later be represented by
   separate deadline/version/hold fields.

Frozen `R-CENSUS-COUNT-01` resolves the descriptive-count boundary: absent
per-view ownership does not block census instrumentation. The census records
only direct lengths of the existing shared lists and reserves ownership/link
semantics for later physical communication research.

The Step-2 essentials are frozen:

- packet identity is the independent census tuple in Section 3;
- the only primary byte quantities are frozen in Sections 7 and 8;
- packet conservation and terminal aggregation are frozen in Sections 10-13.

## 17. Go/no-go decision

```text
READY_FOR_PACKET_CENSUS_INSTRUMENTATION
```

Rationale:

- packet identity is independent, immutable, source-auditable, and does not
  depend on GT, candidates, tracking results, or future outcomes;
- both size definitions are exact computations over current source objects;
- emission and terminal ledgers support one-packet/one-fate conservation;
- Homography held-state reuse and ID remap subevents are excluded from duplicate
  packet terminals;
- `wire_digest` precisely names the unchanged full canonical-wire hash;
- `TIMELY_DELIVERED` makes no downstream semantic-consumption claim.
- `R-CENSUS-COUNT-01` restricts matched/confirmed counts to direct lengths of
  the existing shared payload lists and makes no per-view ownership claim.

This decision authorizes only implementation and synthetic/static validation
of passive census instrumentation. It does not authorize a dataset run, a
packet census run, a bandwidth model, a shared queue, or a scheduler.
